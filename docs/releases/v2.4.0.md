# RAHP Toolkit v2.4.0 — Redbreast Jezebel

**Release date:** 2026-09-22  
**Theme:** VTI Composition Assessment and Evidence-Conservative Reconciliation  
**Codename:** Redbreast Jezebel (*Delias acalis*)

## Release summary

v2.4.0 packages the VTI composition-assessment programme as a stable RAHP capability. The release turns a sequence of evidence-backed VTI composition investigations into a reusable, version-pinned assessment subsystem with machine-readable submissions, deterministic validation, explicit reassessment semantics, programme reconciliation, and truthful residual states.

The release remains additive at the RAHP product layer. It does not change the stable engine/result/evidence compatibility families.

## Major advances

### Version-pinned VTI assessment profile

RAHP now carries an explicit VTI composition assessment profile pinned to `trustoverip/dtgwg-vti-spec` Working Draft 0.1.0 at commit `75391a27a5d9a1794266b2e3bdeb8be68fa4db40`.

The profile maps composition requirement families to RAHP evidence sources, distinguishes verified, specialist-evidence-required and evidence-required states, and records reassessment triggers.

### Machine-readable independent assessment contract

The `rahp-vti-assessment/v1` submission contract captures assessment identity and family, exact VTI source pin, assessed scope and proposition, `supported`/`refuted`/`indeterminate` disposition, evidence references, legitimate counter-cases, residual uncertainty, and reassessment state/triggers.

The contract is intentionally an independent assurance record. It does not claim VTI conformance authority.

### Multi-family executable evidence

The programme now includes current assessment submissions for nine families. Eight are supported: semantic completion; authority continuity; lifecycle and freshness; delegation lineage; false independence; failure and indeterminacy; configuration materiality; and human control.

Each supported family is backed by bounded executable evidence and preserves negative or indeterminate cases rather than inferring support from the absence of failure.

### Privacy remains deliberately indeterminate

`RAHP-VTI-PRV-001` remains `indeterminate`.

RAHP can establish important composition-level privacy boundaries, including the rule that valid proof is not a privacy PASS. However, specialist and runtime evidence remain incomplete across the full privacy interaction surface. The release therefore preserves the DPIP specialist boundary rather than upgrading partial evidence into support.

### Component substitution remains evidence-required

The component-substitution family remains `evidence_required` and has no synthetic assessment submission.

RAHP records the exact evidence gate for `VTI-CMP-100..101`: genuine implementation-pair evidence is required before the proposition can be assessed. A fabricated A/B fixture would not establish substitutability and is explicitly excluded.

### First-class indeterminacy and configuration materiality

v2.4.0 makes two composition properties particularly concrete: `indeterminate` is a first-class trust-evaluation state that cannot be silently rewritten as support or refutation by relying policy; and configuration that alters trust, privacy, authority or security semantics is assurance-material and must remain historically reconstructable.

### Deterministic programme reconciliation

At the v2.4.0 qualification boundary, the profile contains 10 composition families: 8 verified/supported, 1 specialist-evidence-required, and 1 evidence-required. There are 9 current assessment submissions and 0 stale or superseded submissions.

### Upstream packaging without authority collapse

The completed programme prepares a deduplicated clarification package for upstream VTI discussion. It separates downstream assurance evidence from upstream normative authority and avoids duplicating topics already represented by VTI issue #32 and PRs #33 and #35.

No upstream VTI write is part of this release.

## Evidence and claim boundaries

v2.4.0 preserves these invariants:

- missing evidence never becomes PASS;
- workflow success is not assurance success;
- component PASS is not composition PASS;
- normative convergence is not implementation conformance;
- cryptographic validity is not current authority;
- protocol completion is not semantic completion;
- multiplicity is not independence;
- `indeterminate` is not silently promoted;
- specialist privacy boundaries remain explicit;
- synthetic component substitution is not accepted as genuine evidence;
- upstream VTI remains normative and conformance authority.

## Compatibility

No compatibility-family break is introduced:

- `rahp-engine-contract-v1`, revision `1.3`;
- normalized result schema `1`;
- `rahp-evidence-retention-v1`.

The VTI assessment contract is an additive toolkit surface.

## Upgrade guidance

Existing v2.3 users should update toolkit/version metadata and regenerate validation outputs as normal. Consumers adopting the VTI assessment subsystem should pin the exact VTI source revision, use the common submission contract, preserve counter-cases and residual uncertainty, keep stale/missing/contradictory evidence indeterminate or evidence-required, and trigger reassessment on relevant VTI/component/policy/configuration/evidence changes.

Historical assessment submissions remain tied to their original source pin and conditions.

## What this release does not claim

v2.4.0 does not claim universal VTI conformance, universal implementation correctness, complete privacy assurance across all VTI deployments, successful component substitution without genuine implementation-pair evidence, upstream acceptance of RAHP's independent assessment format, or that a supported assessment family proves adjacent composition properties.

The release qualifies the assessment machinery and the bounded evidence actually present.
