# RAHP Toolkit v2.0.0 — Blue Mormon

**Scientific name:** *Papilio polymnestor*  
**Release family:** Portable Assurance Engine Stabilization  
**Compatibility:** product major release; existing portable engine/result/evidence contracts preserved  
**Selected:** 2026-08-30

v2.0.0 marks the point at which RAHP stops treating each newly encountered portfolio proposition as a reason to modify the assurance engine.

The governing rule is now executable:

> A monitored portfolio change should normally change data, instance profile, evidence, or conclusion. It should not routinely change RAHP core.

## Why v2.0

The product major version records an architectural boundary, not a fabricated breaking contract change.

The stable compatibility authorities remain:

```text
rahp-engine-contract-v1 revision 1.3
normalized result schema version 1
rahp-evidence-retention-v1
```

Existing v1.x normalized results, historical assessments, specialist-examination records, and retained evidence remain valid.

### Normalized findings

`rahp-normalized-finding/v1` separates source language from portable assurance semantics. Raw titles and repository names remain provenance/adapter input rather than core routing authority.

Qualifying concepts that are not yet mapped remain explicit as `UNMAPPED`.

### Declarative instance profiles

DTG-specific source extraction and routing semantics live under `instances/dtg/`. Generic finding logic no longer needs Dogwood, relationship-DID, device-heartbeat, or repository-title vocabulary.

### Portable specialist assessor contract

`rahp-assessor-result/v1` requires one finite result:

- PASS
- FAIL
- INDETERMINATE
- NOT_APPLICABLE

with `reason_code`, `evidence_used`, `residual_risk`, and `action_required`.

RAHP validates contract-bearing specialist returns; malformed returns cannot contribute valid portfolio provenance.

### Finite assessment lifecycle

The engine owns:

```text
DISCOVERED
  → QUALIFIED
  → ROUTED
  → ASSESSMENT_REQUIRED
  → EVIDENCE_REQUIRED
  → EVIDENCE_READY
  → ASSESSED
  → TERMINAL
```

Terminal outcomes include PASS, FAIL, INDETERMINATE, NOT_APPLICABLE, and UNMAPPED.

Plugin failure cannot become PASS. Workflow success remains distinct from assurance success.

### First-class clean-room mode

`rahp assess --mode clean-room` resolves engine-owned isolation semantics:

- historical state excluded;
- historical evidence excluded;
- coalescing forbidden;
- fresh assessor lineage required.

Clean-room is no longer merely a lineage string threaded through workflows.

## Portability acceptance

The same stabilized core processes three frozen DTG portfolio snapshots:

- 2026-08-28
- 2026-08-29
- 2026-08-30

without portfolio-triggered core changes.

The validation suite also retains non-DTG/CAWG deployment checks.

The final 30 Aug DTG black-box wave then produced two substantive target FAIL results—device-metadata correlation and an install/admin-DID specification mismatch—without modifying RAHP core. This is positive evidence for toolkit portability even though the DTG consumer portfolio itself is RED.

## Consumer assurance is not toolkit release qualification

The 30 Aug DTG portfolio terminates RED because two target propositions failed. v2.0.0 does **not** claim DTG is GREEN.

The release claim is narrower and stronger: RAHP can now reach evidence-backed consumer PASS/FAIL/INDETERMINATE outcomes without repeatedly patching the generic engine to recognize case-specific vocabulary.
