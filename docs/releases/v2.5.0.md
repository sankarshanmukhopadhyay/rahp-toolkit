# RAHP Toolkit v2.5.0 — Psyche

**Release date:** 2026-09-26  
**Theme:** Continuous Realization Assurance and Portable Adoption  
**Codename:** Psyche (*Leptosia nina*)

## Release summary

v2.5.0 packages the post-v2.4 operating model into a stable additive RAHP capability. The release makes materiality-bounded continuous realization assurance more inspectable and operationally efficient while preserving RAHP's evidence-conservative semantics.

The release combines four mutually reinforcing advances:

- realization-conformance reconciliation that keeps adopted semantics separate from runtime evidence;
- assurance-safe operational telemetry for understanding how RAHP work executed;
- semantic-preserving performance regression controls and measured hot-path optimization;
- a maintained non-DTG portability proof using the unchanged generic RAHP contracts.

The stable engine/result/evidence compatibility families remain unchanged.

## Materiality-bounded continuous realization assurance

RAHP now treats the smallest complete materially affected proposition set as the preferred reassessment scope. Evidence that remains valid can be retained with provenance; stale, invalidated or unavailable evidence remains explicit; and full campaign/rebaseline execution remains available when bounded scope cannot be defended.

The post-v2.4 realization sweep reconciles #799, #609, #691, #797 and #690 without manufacturing closure. Where current target evidence exists, residuals are narrowed. Where the runtime or normative surface is absent or unstable, the durable owner remains EVIDENCE_REQUIRED or WAITING_EXTERNAL with an explicit reassessment trigger.

## Assurance-safe execution telemetry

rahp-execution-telemetry/v1 provides deterministic operational sidecars for run identity, timing, selected scope, lifecycle transitions, blockers and low-sensitivity context.

Telemetry is explicitly non-authoritative:

- it is not target assurance evidence;
- it cannot set or infer an assurance outcome;
- telemetry failure is an observability problem, not an assurance failure;
- raw evidence, credentials, secrets and arbitrary nested payloads are excluded.

This provides useful longitudinal diagnostics without creating a second assurance state machine.

## Performance and execution efficiency

v2.5.0 introduces a versioned performance regression policy and pull-request base-vs-candidate benchmark comparison.

The policy:

- compares like-for-like benchmark contract/profile runs;
- requires semantic reference digests to match;
- uses relative and absolute thresholds to avoid treating hosted-runner jitter as a meaningful regression;
- records performance telemetry as engineering evidence rather than assurance evidence.

The canonical validator also caches immutable YAML inputs for the lifetime of a validation process, removing duplicate parsing without changing records, ordering, warnings, errors, normalized outputs or evidence semantics.

## Non-DTG portability proof

The maintained CAWG/C2PA consumer family now provides an explicit post-v2.4 portability proof.

The proof demonstrates that the same stable RAHP contracts can support:

- a source-pinned bounded first assessment;
- durable residual ownership;
- a real material source change;
- bounded reassessment of only the affected surface;
- baseline advancement with no material assurance impact.

The proof does not establish CAWG/C2PA conformance, universal portability or absence of residuals. Consumer-specific vocabulary remains outside the portable core.

## Documentation and portfolio compatibility

The documentation estate was audited and refreshed around the post-v2.4 operating model, including roadmap, adoption, continuous assurance, telemetry, performance and current cross-repository boundaries.

The maintained portfolio context at this release is:

- RAHP v2.5.0;
- DPIP v0.3.0;
- Trust Protocol Interop Lab v0.7.0.

These repositories remain independently versioned and governed.

## Experimental research boundary

Policy-as-assurance-subject work under #662/#668 remains experimental and is **not** part of the v2.5.0 stable capability boundary.

The research lane retains its own independent-review and graduation requirements. This release does not silently promote it into the stable engine or assurance semantics.

## Assurance and compatibility invariants

v2.5.0 preserves:

- missing evidence never becomes PASS;
- workflow success never becomes assurance success;
- component PASS never implies composition PASS;
- normative convergence never silently becomes realization conformance;
- non-selected evidence is never silently refreshed;
- telemetry and performance metrics are operational evidence, not target assurance evidence;
- performance optimization cannot reduce materially required proposition/evidence coverage;
- the generic core remains independent of DTG, OpenVTC, CAWG/C2PA or other consumer vocabulary.

## Compatibility

No compatibility-family break is introduced:

- rahp-engine-contract-v1, revision 1.3;
- normalized result schema 1;
- rahp-evidence-retention-v1.

## Upgrade guidance

Existing v2.4 adopters can upgrade without changing the stable engine/result/evidence contract families.

Adopters should use materiality-bounded reassessment only when they can defend complete coverage of the affected proposition set. Telemetry should be treated as operational diagnostics. Performance comparison should be used only for like-for-like semantic inputs. A full campaign/rebaseline remains appropriate when materiality, freshness or dependency changes make bounded reassessment indefensible.
