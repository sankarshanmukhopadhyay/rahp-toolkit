# RAHP Toolkit v1.6.0 — Common Earl

**Scientific name:** *Tanaecia julii*  
**Release family:** Source-pinned coverage and guided adoption  
**Compatibility:** additive v1.x release  
**Release-name source:** https://en.wikipedia.org/wiki/List_of_butterflies_of_West_Bengal  
**Selected:** 2026-08-23

v1.6.0 makes RAHP scenario coverage more reproducible, makes corpus growth coverage-driven rather than count-driven, and makes the toolkit easier to enter and operate without changing the stable v1 engine, normalized-result or evidence-retention contracts.

## Added

- source-pinned Trust Tasks and DTG Credential Specification corpora at immutable upstream revisions;
- machine-readable coverage maps for both primary corpora;
- expanded Trust Tasks and Credential Specification coverage from 16 to 30 scenarios each;
- expanded Trust Tasks × Credential Specification composed seam coverage from 12 to 20 scenarios;
- durable preservation of the pre-expansion cross-specification assessment before reassessment;
- v1.6-specific machine-verifiable release qualification and regression tests;
- routed documentation hubs for getting started, development/integration and continuous assurance;
- an idempotent qualified-release workflow that creates the semantic tag and GitHub Release only from a qualified `main` commit.

## Changed

- packaged scenario coverage increases from 146 to **182 scenario vectors** across **14 corpora**, exercising **28 portable scenario patterns**;
- Trust Tasks is pinned to `4937c70df95e56ed6404b8c004106ecb121a23cf`;
- DTG Credential Specification is pinned to `b89f389abbdae77ba60b673c0836c781c2b54169`;
- the Trust Tasks × Credential Specification assessment was rerun against the current source pins and expanded corpora;
- its three existing cross-specification residual themes remain, but are narrowed/refined because current Trust Tasks provides stronger ACL lifecycle, approval, control/corrigibility and removal/redress machinery, while current Credential Specification provides stronger VWC edge binding;
- the root README is now a stable project landing page rather than an ever-growing command/reference handbook;
- detailed operational paths are routed through `docs/getting-started.md`, `docs/developer-guide.md` and `docs/continuous-assurance.md`.

## Evidence-based reassessment result

The expanded corpus did **not** manufacture a new set of findings. Instead, it improved the evidence basis for the existing Trust Tasks × Credential Specification assessment and refined its residuals around:

1. action-time authority and lifecycle coherence across composed evidence;
2. decision, replay, threshold and evidence-closure binding; and
3. privacy and contestability across the complete evidence closure.

This is the intended RAHP behavior: increased scenario coverage should strengthen, weaken, refine or close existing claims according to evidence rather than increase finding count by default.

## Baseline policy

v1.6.0 does **not** silently promote the maintained-example registry from its v1.5.0 baselines. A toolkit release is not evidence that every maintained target was independently reassessed. Historical assessment records remain immutable, and each maintained example advances only through its own evidence-backed retest or reassessment.

## Compatibility

The stable v1 compatibility boundaries remain unchanged:

```text
rahp-engine-contract-v1
normalized result schema version 1
rahp-evidence-retention-v1
```

v1.6.0 is additive within that compatibility boundary. Existing normalized results remain valid.

## Qualification

The release is qualified by `method/v1.6-release-qualification.yaml`, `tools/validate_v16_release.py`, `tests/test_v16_release_qualification.py`, and the repository-wide validation and documentation workflows.

Qualification verifies:

- current immutable source pins and scenario counts;
- composed-corpus dependency pins and reassessment lineage;
- the 182-scenario/14-corpus/28-pattern packaged coverage boundary;
- preservation of historical maintained-example baselines unless separately retested;
- workspace/package version consistency;
- documentation routing surfaces;
- unchanged stable v1 contracts; and
- the qualified publication workflow.

## Release naming

Under the random-at-release-time West Bengal butterfly naming policy, v1.6.0 is **Common Earl — *Tanaecia julii***. The name is presentation metadata only; semantic version `v1.6.0` and the stable method contracts remain the compatibility authority.
