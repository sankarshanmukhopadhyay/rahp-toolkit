## Registry ownership and operational migration

The [RAHP Assessment Registry](https://github.com/sankarshanmukhopadhyay/rahp-assessment-registry) is the external case-administration owner for the configured DTG/CAWG deployment. The Toolkit remains the portable method and canonical execution authority. Other adopters need not install the Registry or inherit DTG-specific state.

- Preflight checks external event batches before issue effects; transfer reservations, exact source binding, authenticated receipts and unique canonical owners prevent duplicate publication (#1218, #1219).
- Four-finding group ownership for historical Toolkit #272 is accepted by Registry #88 (#1225, #1226); unauthorized rollback is rejected (#1227). This is a source-specific administrative transfer, not generalized case migration or assurance PASS.
- Publishers are fenced to current main; external writer registration retirement and publication authority are separated from read-only observation and controller-local incident handling (#1229–#1233, #1250, #1251, #1255, #1256).
- Monitor state is staged through protected-main PRs with scoped App credentials, registration/installation preflight, immutable archive digest checking and stranded-state-branch protection (#1234, #1238, #1242, #1244, #1246, #1247). A successful observation does not imply accepted state.
- DTG/CAWG events are retained with accepted state and indexed by exact producer-bound repository/branch identity (#1253, #1264, #1266). No lowercasing or branch collapse. Indexing is not case admission.
- Combined review workers qualify source snapshot and finding membership before advancing evidence state (#1265). This does not itself supply reviewer judgment.
- Contribution and README guidance identify the actual external-case owner (#1249, #1258). Historical Toolkit cases retain their own lifecycles and are not silently reassigned.

### Operator migration

Use the current Toolkit publication policy and Registry intake contracts. Do not reactivate retired Toolkit external-case writers. Preserve accepted historical records and reconcile unresolved state branches before a new persistence attempt. Distinguish observation, accepted state, Registry admission, canonical execution and substantive assurance. A standalone Toolkit adopter can continue offline without any Registry or App installation. Existing configured operators must review their publication ownership, writer permissions, state PR identity and source-specific transfer ledger before changing deployment configuration.
