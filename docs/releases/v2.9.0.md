## Release scope

v2.9.0 packages 44 post-v2.8 commits into an additive assurance baseline. It does not change the stable engine contract family, normalized result schema or evidence-retention contract.

### Evidence-qualified people-impact methodology

RAHP now has a versioned, machine-validated people-impact pathway layer over selected scenario corpora. It records affected roles, protected interests, plausible consequences, source anchors, countercases and explicit qualification status. The canonical pilot remains evidence-conservative: method capability can be qualified even when no individual causal pathway is independently qualified. Zero-positive output remains a valid result rather than a failure condition.

### Source-qualified corpus evidence and reader path

Scenario corpora now have stronger source-pinning, review-reference validation, glossary coverage and reader-facing navigation. Review backlinks, people-impact pathways and execution evidence remain separate evidence relationships. Source authority is not transferred merely because RAHP indexes or renders it.

### Lifecycle and control-consequence assurance

Credential renewal/reissuance examples and generic control-consequence cases make lapse, coercion, assurance burden, intent leakage and downstream effects testable without creating duplicate catalogue identifiers. Historical validity remains distinct from present continuation authority.

### Runtime, witness and controller evidence

Source-pinned witness semantics, runtime-evidence qualification and controller-routing records strengthen attributable evidence while preserving external or unavailable evidence as explicit residual state. Workflow success and transferred ownership do not silently close substantive assurance obligations.

### Portable assurance registry discovery

RAHP exposes a derived registry index over the canonical portable assurance catalogue. Existing identifiers remain authoritative in `method/catalogue/`; the registry is a discovery projection, not a replacement namespace, API authority or independently governed lifecycle. PR #1128 completes the release-facing discoverability and provenance path by linking the registry from the README and primary data model, adding contributor rebuild/check guidance, and finalizing the #1123 feasibility record.

### Release and contribution assurance

Release Actions are pinned to immutable revisions, qualification is separated from write-authorized publication, Python release dependencies are hash-locked for the governed runner, representative ephemeral artifacts use the declared retention contract, and repository-native DCO checks now protect contribution certification. Code/content licensing is also explicit.

## Known limitations

- Independent external adoption remains **NOT_YET_TESTED**.
- The people-impact pilot establishes method behavior, not independently adjudicated real-world causal harm pathways.
- Deployment/runtime evidence is source-pinned and bounded; it is not deployment certification.
- Admin-level Actions permission ceilings, raw log-retention settings and private environment administration tracked by #958 remain **NOT VERIFIED** where the available repository interface cannot inspect them.
- Independent attributable human security review remains a separate evidence obligation under #958.
- The assurance registry is derived discovery metadata and must not be treated as catalogue authority.
- Source-specific corpus assertions remain bounded to their recorded pins and review evidence.

## Migration

No migration is required for the stable engine/result/evidence contracts. Consumers may adopt the new people-impact, source-reference and registry-discovery surfaces incrementally. Existing catalogue identifiers and terminal assurance semantics remain unchanged.
