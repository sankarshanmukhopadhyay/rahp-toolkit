# RAHP Toolkit v1.8.0 — Common Map

**Scientific name:** *Cyrestis thyodamas*  
**Release family:** Semantically Governed Assurance Pipeline  
**Compatibility:** additive v1.x release  
**Selected:** 2026-08-28

v1.8.0 strengthens RAHP's assurance operating model from change detection through evidence gathering, bounded disposition, human judgment, specialist privacy examination, and final portfolio reconciliation.

The release does not change the stable v1 engine, normalized-result, or evidence-retention contracts.

## Added and qualified

- gatherer-native end-to-end lineage for material DTG repository changes;
- direct advancement of newly published assessment work items without depending on eventual-consistency issue rediscovery;
- bounded evidence-backed automatic disposition before human escalation;
- polarity-aware assurance evidence rules that distinguish weakening/introduction from fixing/prevention;
- reviewer-ready judgment packets for unresolved semantic questions;
- explicit DPIP applicability and canonical RAHP → DPIP → RAHP return lineage;
- semantic materiality classification that separates substantive changes from generated/codegen and release fan-out;
- structured VTI composition and adversarial false-independence evidence registers.

## Semantic materiality

v1.8.0 makes materiality more proposition-sensitive.

The DTG gatherer now distinguishes:

- normative changes;
- security-sensitive changes;
- implementation-semantic changes;
- dependency/manifest changes;
- generated/codegen output;
- tests/evidence;
- release metadata and propagation.

Numeric weights are explanatory only. Routing remains governed by explicit classes.

This means:

- one normative/security/semantic change remains assessment-worthy even when surrounded by many release files;
- dependency or ambiguous manifest changes remain conservative;
- generated convergence can be triaged without becoming a fresh broad assessment;
- pure bounded release propagation can remain informational.

The #151 and #183 revision patterns are preserved as regression evidence. #183 specifically proves generated TypeScript binding convergence plus package/changelog propagation can be classified as triage rather than a new broad RAHP/security assessment.

## Bounded automation and judgment

RAHP may automatically disposition a gathered revision only when explicit evidence-sufficiency rules make every required lens terminal.

Otherwise the workflow stops at `judgment-required`.

This preserves the core rule:

> **workflow success is not assurance success.**

Missing, ambiguous, or contradictory semantic evidence remains uncertainty rather than being converted into a PASS.

## Privacy escalation

v1.8.0 preserves RAHP as the bounded composition-level assurance controller and DPIP as the specialist privacy examination path when warranted.

DPIP applicability must be explicit. A returned `INDETERMINATE` conclusion remains non-green and must not be converted into privacy assurance.

## Continuing evidence programmes

The VTI composition evidence register and adversarial identity/trust-independence register are intentionally **continuing** programmes.

In particular, #193 and its indexed Sybil, sock-puppet, trust-laundering, false-diversity, collusion, selective-evidence, and quorum-capture issues remain open pressure-test candidates.

v1.8.0 qualifies the taxonomy, evidence structure, and assurance machinery used to develop those cases. It does **not** claim complete adversarial-independence coverage.

## Compatibility

```text
normalized result schema version 1

```

Existing normalized results, historical assessment records, and release qualification evidence remain valid.
