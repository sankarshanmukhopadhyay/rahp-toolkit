# RAHP Toolkit v1.9.0 — Lesser Mime

**Scientific name:** *Papilio epycides*  
**Release family:** Portable Clean-Room Assurance  
**Compatibility:** additive v1.x release  
**Selected:** 2026-08-30

v1.9.0 qualifies clean-room assurance as a reusable RAHP capability rather than a target-specific experiment.

The release preserves the stable v1 engine, normalized-result and evidence-retention contracts.

## Added and qualified

- a generic declarative clean-room executor driven by repository run specifications rather than target-named workflow files;
- immutable target and auxiliary-resource pinning with explicit exclusion of historical assessment inputs;
- declarative evidence-probe plans with mandatory attempt state and producer attribution;
- machine-readable and human-readable evidence-stage records separated from semantic assurance judgment;
- explicit experiment-role semantics distinguishing detector-sensitivity positive controls from context-distinct unlinkability pressure cases;
- clean RAHP → DPIP → RAHP lineage where a fresh assessment produces a fresh specialist examination when privacy is material;
- preservation of `INDETERMINATE` as non-green and of missing evidence as missing rather than PASS;
- workflow rationalisation that removes superseded target-specific clean-room entry points and adds an executable regression guard.

## Target-adapter portability evidence

Interop Lab issue #71 and PR #72 add a target-native context-distinct VTI Dogwood RC-1 pressure adapter while leaving RAHP's generic clean-room executor and the Interop Lab generic A/B classifier/exporter target-agnostic.

The existing same-relationship A/B case remains a positive control with `must-detect` semantics. The new target-native pressure case begins A and B with distinct deterministic client identities and uses `must-not-emerge` semantics.

This evidence demonstrates the intended architecture:

```text
target adapter / run specification
        ↓
generic runtime observation contract
        ↓
generic A/B classifier + attribution
        ↓
RAHP clean-room evidence production
        ↓
fresh semantic RAHP assessment
        ↓
DPIP examination iff privacy is material
        ↓
RAHP reconciliation
```

## Assurance boundaries

A green workflow proves only that the declared execution completed successfully.

It does **not** mean:

- a target received a global privacy PASS;
- a positive-control join is a target privacy failure;
- composition evidence can be promoted to target-native evidence;
- unexercised status, policy or Trust Task surfaces are assumed to pass;
- prior assessment or DPIP records may be rewritten in light of new evidence.

Historical assessment and specialist-examination records remain immutable lineage evidence. New evidence creates new comparable assessment/examination lineages.

## Workflow governance

The repository workflow audit removed the superseded `clean-room-dogwood.yml` and `true-clean-room-dogwood-248.yml` entry points. `clean-room-assessment.yml` is now the sole clean-room executor, with a governance check preventing target/issue-specific clean-room workflows from quietly returning.

Mechanically similar lifecycle controllers remain separate where they own different event contracts or assurance state transitions. Workflow count is not treated as an optimization target when consolidation would hide semantic ownership.

## Compatibility

```text
normalized result schema version 1
rahp-evidence-retention-v1
```

Existing normalized results, historical assessment records and evidence-retention semantics remain valid.
